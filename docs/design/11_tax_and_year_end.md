# 11 税務・決算・年度繰越

版1.0 / 2026-10-23。対象年・利用者条件・正式資料を確認した範囲だけを申告計算へ有効化する。

## 1. 税務profile

個人事業の一般用青色決算を中心にし、白色の集計も設定で分ける。プラットフォーム収入であることだけで事業所得/雑所得を自動決定しない。

| 設定群 | 必須情報 |
|---|---|
| 事業 | 開始/廃業、業種、会計期間、初期残高 |
| 所得区分 | 事業、不動産等の適用範囲、他所得の有無 |
| 青色 | 承認/届出状況、記帳方法、控除候補、期限内条件 |
| 消費税 | 課税/免税の判定根拠、基準/特定期間、登録/選択、方式 |
| インボイス | 登録番号、登録/失効日、取引時の条件 |
| 経理 | 税込/税抜、適用開始、税計算と端数方針 |
| 申告 | 対象年、本人情報、公式手続、書類対応状態 |

売上が少ないという理由だけで免税にせず、登録や選択等を確認する。未確認はunknown。現在の設定を過去年度へ遡及上書きしない。

## 2. 売上と経費

収益は原則として収入すべき権利の確定等を取引条件から判定する。請求日/入金日/プラットフォーム確定日を同一日扱いにしない。現金主義の特例は条件と届出を確認した別mode。

経費は事業関連、期間、支払・未払、家事分、資産性を確認する。家事按分は対象・期間・割合・根拠を保持する。月次按分と年末調整を重ねない。

源泉所得税は受取純額との差として保持し、必要経費に混ぜない。支払者、報酬総額、支払日、源泉額、資料の対応を申告情報として残す。未確認源泉はnull。

## 3. 消費税の構造

税区分は税率だけで表さず、課税/非課税/不課税/対象外、売上/仕入、国内外、適格性、経過措置、免税事業者等との取引、事業割合、方式を構造化する。

tax_amount_statusはunknown/known/not_applicable。knownの0とunknownのNULLを区別する。領収書のT番号の有無だけで控除可否を確定しない。カード会社請求明細だけで必要な請求書等が揃うと仮定しない。

一般課税・簡易課税・適用可能な特例は対象年と本人条件で選ぶ。未実装方式を一般課税の式へ代入して結果を出さず、集計資料を作り公式手続で補完する。

## 4. 年版rule

rule_key、version、適用開始/終了、対象年、条件式、algorithm版、端数処理、公式出典、確認日、承認、test fixtureを持つ。税率、控除、特例閾値、様式mappingをコードへ散在させない。

2026-10-23確認の国税庁資料には、2027年分から一定条件下で最高75万円の青色申告特別控除が示されている。2026年分へ先行適用しない。また、免税事業者等からの仕入れに係る経過措置は2026-10-01から70%の期間が示されている。旧予定や古い説明の50%を固定しない。

これらは日付付きruleが必要な実例。個々の控除適用をアプリが未確認の利用者へ自動認定するものではない。制度案はproposal、成立/公布/施行と分け、AI通知だけでruleを公開しない。

## 5. 固定資産

asset_id、品名、取得日、供用日、取得価額、消費税経理方式、数量、事業割合、資産区分、耐用年数、償却方法、率、前期末未償却、増減、除売却日、選択した特例、根拠を保存する。

10万円等の一般基準、一括償却、青色の少額特例は取得日・供用日・対象者・年間限度等をruleで判定する。国税庁No.2100は令和8年4月1日現在資料のため、旧来の特例閾値を永続固定しない。

帳簿額と税務計算、家事割合、月数、端数、売却損益を分ける。資産の名称だけで耐用年数をAI確定せず候補と根拠を示す。資産台帳と決算整理仕訳を照合する。

## 6. 個人申告情報

帳簿以外の給与/年金等所得、社会保険料、生命/地震保険、医療費、寄附、扶養等の控除情報は独立入力とする。証明書と確認状態を持ち、未対応の分離課税や損失特例を検出する。

マイナンバー・PIN・認証tokenはAI snapshotへ含めない。本人識別情報の取扱いは最小化し、E1/E2では可能な項目を公式手続で本人が入力する。保存する個人情報は暗号化・出力権限を別に管理する。

## 7. 計算の流れ

会計集計→必要な税務調整→青色控除等の適用判定→所得区分別金額→他所得/損益通算等の対応範囲→所得控除→課税所得→税率/控除→復興特別所得税等→源泉/予定納税等→納付/還付を年度ruleで処理する。

端数処理は各段階の規則を用いる。すべて最後に四捨五入する実装にしない。各結果は入力ID・適用rule・計算経路に逆引きできる。未入力や対象外を0へ補って「正確な税額」と表示しない。

## 8. 決算workflow

open → preclose → adjusted → reviewed → frozen。月次はopen/reviewing/soft_closed。凍結で通常記帳を止める。凍結前の帳簿変更は確認結果とsnapshotをstaleにし、必要な工程へ戻す。

事前確認は取込coverage、未確定、重複、残高照合、証憑、売掛/未払、棚卸、前払/未払、家事按分、資産、源泉、事業主貸借、他所得、控除、年版対応。試算表と決算書、P/LとB/Sの控除前所得を照合する。

## 9. 凍結snapshot

snapshotは仕訳集合、ledger_revision、audit cutoff、open item movements、allocation/cancel ID集合、rule/profile/mapping/algorithm版、原本参照、入力値、計算結果を固定する。

後日バックデートした消込取消が、以前の凍結結果へ紛れ込まないようにする。ledger_revisionだけでは不十分。読取snapshotと入力manifestで再現性を持つ。

## 10. 年度をまたぐ債権債務

open_item_idは継続し、翌期openingは残高投影だけを作る。前年売掛行と翌期opening行を別々の債権として扱わない。

as_ofの業務日条件と、凍結時の記録境界を両方適用する。例: 12月売掛110,000円、1月10日回収66,000円なら12月末110,000円、1月10日44,000円。1月15日付取消で1月10日の残を変更しない。

## 11. 元入金の繰越

通常方式はclosing_method=opening_projection。

翌期首元入金
= 当期首元入金 + book_profit + 事業主借純増 − 事業主貸純増 + 明示した資本調整。

book_profitは青色控除前の帳簿利益で、個人の課税所得や税務だけの調整後所得とは区別する。決算書への転記に差が出る場合は根拠を表示し照合を完了させる。翌期首の資産純額−対外負債でも元入金を照合する。

期首元入金1,000,000、利益600,000、事業主借100,000、事業主貸300,000なら翌期首1,400,000円。資産2,100,000−負債700,000でも一致。利益が負の場合はその分減少し、資本が負でもゼロへ丸めない。

事業主貸借と損益は翌期へ同じ残のまま持ち越さず、元入金へ整理したopening projectionを生成する。前年の利益振替と翌期の利益加算を両方実行しない。当年のB/Sの元入金表示と翌期首元入金を混同しない。

## 12. 前年訂正

前年snapshotを変更しない。再開・訂正・新版snapshotを作ると、翌期carryforwardをopening_staleにする。carryforward_revisionに旧/新snapshot、target year、元opening、差額調整entryを連結する。

前年費用/未払20,000円の追加なら、例の翌期元入金は1,380,000、対外負債720,000へ変わる。翌期の費用を20,000増やして補正しない。翌々期にも影響する場合はstaleを連鎖させる。

## 13. 本番化と受入条件

対象年の公式手引き・正式様式・e-Tax仕様・控除/税率・経過措置を確認し、境界日前後、0/不明、返金、赤字、按分、減価償却、源泉、年跨ぎ、繰越、前年訂正を検証する。

未検証の年版はpreview/転記資料までに制限し、提出用適合と表示しない。青色承認・消費税選択等の利用者条件を未確認のまま有利な方式へ自動選択しない。
