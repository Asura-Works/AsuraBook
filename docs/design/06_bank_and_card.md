# 06 銀行CSV・クレジットカード自動取得

版1.0 / 2026-10-23。利用銀行・カードは未指定。具体的な提供元対応は実サンプルと契約を確認して有効化する。

## 1. 取得経路

| 経路 | 初期の位置付け | 完了条件 |
|---|---|---|
| 銀行CSV | 必須、選定銀行から開始 | 入出金・残高・日付・口座が実資料と一致 |
| カードAPI | 要件として必須、外部契約に依存 | 利用者認可の下で対象カードを継続取得 |
| カードCSV | API未対応時の正式な代替 | 請求月と利用月を区別して解析 |
| フォルダ監視 | 受領済みCSVの自動処理 | コピー完了・重複投入を検出 |

CSVの監視はWebサイトからの自動取得ではない。画面には「取得方法: API / CSV手動 / フォルダ監視」を表示し、機能の達成状況を混同しない。

## 2. 銀行profile

銀行名、個人/法人、口座商品、CSV画面、encoding、header版、列対応、日付形式、摘要、入金/出金/残高、表示順、対象期間、件数上限、口座識別方法を固定する。

取得範囲が画面期間で変わるため、ファイル最初/最後の日付だけで全期間取得済みと判定しない。明細なしの日・月は「0件を確認済み」と「未取得」を分ける。銀行AとBの振替をそれぞれ売上・経費にしない。

銀行amountは入金正・出金負へ正規化する。元の入金列・出金列・残高・摘要を保持する。両方に金額がある行、残高連続性が崩れる行、合計行、日付なし行はprofileに基づき保留する。

三井住友銀行公式案内は、表示順がCSVへ反映され、画面の「－」も出力されることを説明している。特定銀行の列を推測して全銀行共通にしない。

## 3. カードの共通モデル

charge、refund、payment、fee、interest、installment_scheduleを区別する。利用日、確定日、請求月、引落日、加盟店、カードaccount、外部ID、未確定/確定状態、通貨、円確定額を持つ。

利用時に費用または資産/未払金を作り、銀行引落しは未払金/預金とする。家族カード・複数カードを末尾4桁だけで統合しない。分割払いは購入総額、元本返済、手数料を分け、月次請求額を毎月全て新費用にしない。

楽天カードの公式CSV案内には請求確定分を月単位で出力すること、一明細が複数行になる場合、一部項目がCSVへ収録されない場合が記載されている。このような範囲不足をcoverage情報へ反映する。

## 4. API Provider

Moneytree LINK等の正式な金融データ連携を候補とする。公開資料でAPIの存在が確認できても、個人開発者の契約、料金、Windowsデスクトップのredirect方式、対象カード、更新頻度、履歴取得期間は確認が必要。

採用前に次をProvider契約書・仕様・検証環境で確定する。

- clientの種別、PKCEの可否、redirect URI登録、client secretの保管場所。
- 対象金融機関・カード・account種別、利用者認可と失効手順。
- cursor、ページング、更新/削除イベント、未確定から確定へのidentity。
- rate limit、再認証、追加認証、取得履歴範囲、利用料金。
- APIレスポンスの保存許諾・保持条件。

public native clientとして認められないsecretをデスクトップexeへ埋め込まない。confidential clientが必要なら、契約とscopeに合う小規模gatewayでtoken交換を行う。汎用の証憑upload APIと権限を分ける。

## 5. 認可と秘密

利用者はシステムブラウザでProviderへ認可する。state/PKCE等は採用方式に従う。銀行・カードのログインパスワードをTaxDeskへ入力・保存させない。公開されていないAPI、ログイン画面の無人操作、MFA回避を標準経路にしない。

tokenはWindows Credential Manager等の利用者保護領域に置き、SQLiteには参照IDと期限状態だけを残す。scope、同意日、Provider、最終成功、取得対象accountを記録する。連携解除で将来取得を停止してtokenを失効させ、過去の会計原本を勝手に削除しない。

## 6. 同期アルゴリズム

連携状態を検査→対象accountを確定→前回成功cursorまたは期間から取得→全ページの原資料を保全→観測をupsertではなく履歴追加→正規化identityへ関連→coverage更新→照合候補まで、の順とする。

ページ途中失敗は取得済み範囲と未完了範囲を保存する。成功cursorを未取得ページの先へ進めない。再取得期間を重ねて欠落を防ぎ、重複は安定IDで統合する。外部で一時的に消えた明細を正式取消にしない。

認証切れはauth_required、rate limitはretry_wait、形式変更はschema_changed。バックオフとjitterを使うが、同じ認証失敗を無制限に繰り返さない。

## 7. 画面と残高照合

連携一覧へProvider、account、取得方法、最終成功、取得範囲、未解決、再認可要否を表示する。更新ボタンの押下を即「同期成功」にしない。

銀行の基準時点残高と帳簿残高を比較し、差額だけでなく未取込・未確定・締め済み遅着を示す。カード未払は利用確定額・返金・引落し・請求調整を含めて照合する。請求額と未払残高は基準日が異なるため無条件一致を要求しない。

## 8. 本番化ゲート

実際の銀行CSVの正常・返金・同日同額・期間重複・文字化け・列変更を検証する。カードAPIは対象カード実明細、認可、失効、再認証、ページング、状態更新、再取得を検証してから「自動取得対応」と表示する。
