# 性能測定

`scripts/benchmark.py` で測った参考値です。01章4節の目標は「10万仕訳規模で日付索引検索を概ね1秒以内」です。

- 規模: 仕訳 100,000 件 (明細 200,000 行)、DB 121.5 MB
- 環境: Python 3.13.16 / SQLite 3.45.1 / Linux-6.18.44-fc-v153-x86_64-with-glibc2.39 (クラウドのLinuxコンテナ)
- 測定日: 2026-10-23
- **Windows 11 実機・ウイルス対策ソフト有効の環境では測っていません。** 実機では値が変わります。

| 操作 | 条件 | 中央値 (ms) | 最大 (ms) |
|---|---|---:|---:|
| 仕訳一覧 | date_from=2026-06-01, date_to=2026-06-07 | 8.6 | 11.4 |
| 仕訳一覧 | date_from=2026-06-01 | 5.8 | 8.8 |
| 仕訳一覧 | text=取引先123 | 365.9 | 485.1 |
| 仕訳一覧 | account=514, date_from=2026-11-01 | 8.7 | 8.8 |
| 仕訳一覧 | amount_jpy=12345 | 0.2 | 0.8 |
| 試算表 | 年度全体 | 477.0 | 574.6 |
| 損益計算書 | 年度全体 | 505.9 | 519.1 |
| 総勘定元帳 | account=110, date_from=2026-12-01 | 206.8 | 224.8 |
| ダッシュボード | 年度全体 | 495.1 | 578.7 |
| 申告前チェック | 年度全体 | 2368.7 | 2368.7 |

所見:

- 日付・科目・金額で絞る検索は 10ms 未満で、目標を満たします。
- 摘要の部分一致検索 (LIKE '%...%') は索引が効かず約0.4秒です。全文検索が必要になれば FTS5 を検討します。
- 試算表・損益計算書・ダッシュボードは年度全体の明細を集計するため約0.5秒です。
- 申告前チェックは約2秒です。帳簿全体を点検する手動実行の処理として許容しています。
- 測定のため試験データは SQL で直接作成しています (確定仕訳の trigger・制約は通ります)。測定自体は Core.execute 経由です。

再測定: `uv run python scripts/benchmark.py --entries 100000`
